## Recommended Project Title

**E-Commerce Customer & Sales Intelligence — SQL, Python & Power BI Analytics Project**

## Tech Stack Line

`SQL (SQLite) · Python (Pandas, Matplotlib, Seaborn) · Power BI (DAX) · Jupyter Notebook · Git`

## 1-Line Project Description

End-to-end analysis of ~100K real e-commerce orders — SQL + Python for cleaning/analysis/RFM
segmentation, Power BI for an executive dashboard — surfacing evidence-based insights on sales,
customer retention, and delivery performance.

## Resume Bullets (pick 3-4 based on the role you're applying for)

1. Cleaned and analyzed a 9-table, ~1.1M-row real-world e-commerce dataset (Olist, Brazil)
   using Python (Pandas) and SQL, resolving data-quality issues including duplicate records,
   inconsistent types, and referential mismatches, and documenting every cleaning decision.

2. Wrote 25+ SQL queries (joins, CTEs, subqueries, window functions) across 6 analysis modules
   to answer sales, customer, product, regional, and delivery business questions on a
   SQLite database of 99,441 orders totaling R$15.4M in delivered-order revenue.

3. Built a rule-based RFM customer segmentation (Recency/Frequency/Monetary) in SQL,
   identifying that only 3.0% of 96,096 unique customers are repeat buyers and isolating an
   "At Risk" segment (22,690 customers, R$266.82 avg. historical spend) as the highest-ROI
   retention target.

4. Designed a 3-page Power BI dashboard (data model, relationships, DAX measures) visualizing
   sales trends, customer segments, and delivery KPIs; uncovered that on-time deliveries
   average 4.29★ customer ratings vs. 2.57★ for late deliveries — the project's strongest,
   most actionable insight.

## Notes on using these bullets

- Bullet 3 and 4 have the strongest, most specific numbers — prioritize these if space is
  limited.
- If asked in an interview "how did you verify these numbers," you can point directly to the
  SQL query / notebook cell that produced each one (see `docs/03_sql_learning.md` and
  `docs/07_business_insights.md`) — every number here is traceable to a real, executed query.
- Do not add a "%" improvement/accuracy claim beyond what's written here — none of these numbers
  represent a comparison to a previous state (there is no "before" project), so phrases like
  "improved X by Y%" would not be accurate for this project.
